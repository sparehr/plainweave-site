Security and data handling

What we access, what we keep, what we never do.

For the person who has to approve access. This describes how the Plainweave Audit is built today, including what is not finished.

Access

  • Read-only by construction. Connectors are built on a transport that can send only read requests: GET, plus a query-only POST to an allow-listed set of provider query endpoints. There is no write, send or delete path to misuse.
  • Least scope, shown to you. Each connector lists every permission it requests and why. That list is what you approve.
  • Metadata first. Each connector keeps an allow-list of fields and drops the rest, including titles, message text and file bodies, before anything is stored.
  • Content is a separate grant. Without your explicit approval for the engagement, a content request is refused.
  • You can revoke at any time from your own admin console. Collection stops.
  • Paper and older systems need no access. We take walkthrough answers, CSV exports you send, and photos of blank forms. There is no connection into a system on your premises.

Storage and isolation

  • One isolated store per client. A separate database per company, with no shared tables.
  • Evidence is hashed. A finding whose evidence has changed since it was stored is rejected.
  • No silent partial lists. A list longer than a connector's page limit, or a provider that sends the same page cursor twice, is never passed on as complete. The fetch stops, or the record says the list is incomplete. Where a provider itself can shorten a list, such as Stripe invoice lines, the record says it may be short.
  • Only verified findings leave the store, with exactly the records they cite. Exports are bound to your company and rejected anywhere else.
  • Credentials are never stored with evidence.
  • Deletion on request and at the end of the engagement.

Models

  • Model calls run through one audited module on commercial API terms, never personal accounts.
  • We do not train models on your data.
  • Agents have no tools that act on your systems. They read evidence and write findings.
  • A photo of a blank form is sent to the model once, to read its field labels. It is not stored by Plainweave afterwards.

Not in place yet

  • No live run. No connector has read a real workspace, and no app is registered with any provider yet.
  • No SOC 2 report. Not started. We will say so until it exists.
  • Per-client encryption keys. Today the data volume is encrypted as a whole.
  • Signed exports and a fixed retention schedule. Planned with hosting.
  • Data processing agreement. A draft will be provided before any access is granted.
